Widget 104 representation · animating the network diagram

Three motions for the schematic in the formula card, each movement only (nothing fades), each mark in its own lane. They loop here so they can be judged; in the widget each would run once, tied to a press. The forward pass is in ink; the gradient in --c-slope (the role for a slope or gradient arrow); the encoder is the solid box throughout.

1 · The options

A · a forward pass, then the gradient back (Autoencoder)

during Train: one pass per move between checkpoints (nine), 500 ms each

B · keep the encoder, drop the head (Autoencoder)

when Train ends: the head slides out to the right; z points at the maps below

A on Masked

the same pass; the loss is on the hidden part only

C · two views through one encoder (Contrastive)

Augment: x splits into the two views; Train: both branches forward, the gradient back along both to the same encoder

Recommend A (and C on Contrastive) with B at the end. A says what Train does in one picture: data goes forward, the loss sends a gradient back, and only the network's weights change (the boxes do not move). C shows the contrastive point the matrix cannot: the gradient from both branches reaches the same encoder. B ties the diagram to the maps: the map on the right is drawn from z, the encoder's output, with the head gone. Each moving mark has its own lane: the forward dot on the arrows, the gradient on a return line under them, the head along its own row.

2 · The calls

2.1 · During Train A, a forward pass and the gradient back for each move between checkpoints (rec) · one pass at the start of Train only · none.
2.2 · Contrastive C: Augment splits x into the two views; Train runs both branches and the gradient back to the one encoder (rec) · as A, one branch drawn.
2.3 · When Train ends B, the head slides away and z points at the maps (rec) · nothing.
