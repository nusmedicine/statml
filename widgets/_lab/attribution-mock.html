3 · Common, and per widget

It belongs in core: every widget page is built by one function, buildShell in widgets/core/widget.js, and the Copy link row is made there for all 77. One constant there is the common attribution; a widget overrides it through defineWidget, the door every per-widget setting already uses (the manifest is for gallery cards and nothing else, so the widget page does not read it). Two forms of override, both shown:

the common line (76 widgets today: no field)

Kenneth Ban, NUS Medicine

attribution: "…" replaces it

Kenneth Ban and A. Colleague, NUS Medicine

credit: "…" adds to it

Kenneth Ban, NUS Medicine · Data: MetaboLights MTBLS6038
// widgets/core/widget.js — the one common line
export const ATTRIBUTION = "Kenneth Ban, NUS Medicine";

// a widget, only when it differs
defineWidget({
  slug: "…",
  attribution: "Kenneth Ban and A. Colleague, NUS Medicine",   // replaces the common line
  credit: "Data: MetaboLights MTBLS6038",                      // or adds a source after it
  …
});

Both forms, recommended. attribution replaces the line for a widget someone else wrote or co-wrote; credit keeps the common line and names a source after it — the case the collection already has (85's HA proteins from BV-BRC, 70's look-alike signature references in place of COSMIC's, 91's metabolite names from MTBLS6038). A replace-only override would make every widget that cites a source restate the common line, and the restated copies drift. No widget sets either today; the draft would add the core field and nothing else. check can assert that both are short strings and that no widget restates the common line in attribution.
