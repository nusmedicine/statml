processing-layers · Attention — three ways to show what the Sum means

Band 2 today draws three rows of [w_j] cat–token · [v_j, four cells], an arrow labelled Sum, and the output row of four cells. The arrow is the only thing that says how the four output numbers were made. What the sum means is that the output for a query is the weighted average of all three tokens' value rows, the weights being that query's attention weights, which sum to 1 — so the output lies between the value rows and moves toward whichever token the query weights most. These three options draw that, at the real 550 stage (PAD 14, so 522 usable, right edge 536; cell 46 × 26, operator column 26, row pitch 34), for the query cat, each at both projections.

Every number is the widget's own: model.js's attention() off makeRng(1) — the page's default seed — at projection=random and at projection=identity. Nothing here is invented and nothing uses Math.random.

Two colour notes, both decisions rather than accidents. The weight cell and the products take the highlight ramp — --c-highlight at an alpha equal to the weight — so a product's shade says which weight built it; band 1's weights grid uses the same ramp in --c-empirical, so if an option ships, one of the two ramps moves and they should be the same one. The output row is --c-empirical here, including in the "today" panel, where the page draws that cell in the highlight lit face because the walk has just landed on it; drawn against three highlight-shaded product rows the sum needs a face of its own. Value rows stay --c-group-b, as the page draws V.

What the numbers actually say

    Today

    Band 2 exactly as drawAttn builds it, at both projections, so the options are measured against a picture and not against a memory of one.

    A · the weighted rows, then the column sum

    Each row becomes its own line of arithmetic — w_j · v_j = the product row — with a + between the products, a rule under them, and the output as their column-wise total. The products sit beside the value rows rather than under them, which is what keeps the cost to one output row and one printed line instead of three more rows; the price is the row label, which shortens from the pair cat–The to the key token, because pair label + values + products measures 538px against the 522 available. One feature's arithmetic is written under the total, and that feature's column is framed through the stack.

    B · the running sum, stepped

    The output starts empty and each weighted row is added in turn, the output cells carrying the running total after each addition. Three moments within one query — drawn here stacked so the accumulation is readable on a still page; the widget would show one moment at a time, so its cost is one copy, not three.

    C · one feature as stacked bars

    Beside the number grids, a signed bar chart: for each of the four output features, the three products w_j · v_j stacked end to end from zero, the stack's end being the output value, with a rule in --c-empirical where the output cell below prints it. All four features are drawn, so no feature control is needed.
