cnn-architecture · the depiction, round 3

What this page answers. Three of your four points: a nicer depiction of the architecture (2), a detail section that shows the result of each operation (3), and the missing link at the third block (1). The fourth — a motif the later lessons can reuse — is §4, an API sketch rather than a drawing.

The engine is real. The 28 × 28 input is the draft's own texture: a blob, a smaller blob, and noise, on a grey ramp. Four named 3 × 3 kernels run over it — horizontal edge, vertical edge, blur, centre-surround — then ReLU, then 2 × 2 max pooling; four more named kernels run over the pooled maps, then ReLU and pooling again. Every feature map on this page is that arithmetic, drawn nearest-neighbour on the same grey ramp and scaled by its own largest value. Nothing is trained: the kernels are named operators, not learned filters, and the page says so wherever it draws one.

Four channels of thirty-two. A convolution here computes four maps where the network computes 32 or 64, and each second-block map runs one kernel over the pooled map of the same index. The real layer reads every input channel. Both facts are printed on the figures that depend on them.

§1 · The architecture depiction

The same network four ways — input 28 × 28 drawn as one grey channel, conv1 32, pool, conv2 64, pool, global average pooling, Linear 9 — each carrying the feature maps' real content. A a gallery of feature maps, a column per stage (the CNN Explainer arrangement, Wang et al. 2020). B slabs in a shallow isometric, one channel's map on the front face and depth following the channel count (your conv2d figure's convention, and NN-SVG's LeNet). C the draft's own flat rectangles — height following H, width following C, your U-Net figure's convention — with a map drawn inside each rectangle. D the chain of labelled boxes torchvista.trace_model prints, a shape on every edge and a thumbnail beside each box.
