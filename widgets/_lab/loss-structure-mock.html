What the standard sources do with binary. PyTorch's own documentation splits the two by shape rather than by task: CrossEntropyLoss is described for a classification problem with C classes, taking unnormalized logits and a class index; BCEWithLogitsLoss is described as combining a sigmoid layer with BCELoss, and is the loss named for binary and for multi-label targets. The textbooks frame the two forms as one model: Bishop's Pattern Recognition and Machine Learning §4.3 derives two-class logistic regression with a sigmoid and the K-class case with a softmax, and Goodfellow, Bengio and Courville's Deep Learning §6.2.2 pairs a Bernoulli output with a sigmoid unit and a multinoulli output with a softmax unit. The two forms are the same model: softmax over two logits gives p_B = e^{z_B} / (e^{z_A} + e^{z_B}) = σ(z_B − z_A), so a two-output softmax head and a one-output sigmoid head on the difference return the same probability and the same loss — verified on torch 2.14 in _lab/dl-loss-torch.py §6 to 1.2e−07 over the whole drag. What the sources do not agree on is where binary belongs in a taxonomy: scikit-learn's user guide keeps binary, multiclass and multilabel as three separate target types, while PyTorch has no binary loss at all — binary is a shape either loss can take. That disagreement is the whole of Kenneth's question, and it is why the widget has to choose.

What the host does. 05-4 cell 30's table has three rows by task — Regression (nn.MSELoss), Single-label classification (nn.CrossEntropyLoss), Multi-label classification (nn.BCEWithLogitsLoss) — and then three sections by function: MSELoss (31–33), CrossEntropyLoss (34–36), BCEWithLogitsLoss (37–39). The BCEWithLogitsLoss section is the one that names binary, and it names it alongside multi-label: “can be used for binary classification, where a sample can be classified with a single label…; multi-label classification, where each sample can belong to multiple classes at once”. Cell 29's own workflow MLP ends in nn.Linear(hidden, num_classes) with num_classes = 2 and CrossEntropyLoss — binary as two outputs. So the notebook itself puts binary in two places under two functions, and never says they are the same model.
