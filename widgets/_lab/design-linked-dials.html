Linking the Replicate tab's two dials

Kenneth, 2026-09-05: "if sliders can link so we can keep the number of measurements constant without me calculating that 10 x 1 = 2 x 5". The tab's argument is how ONE budget is split between people and repeats, and today the two dials float independently — so holding the budget fixed is arithmetic the reader has to do before the comparison even starts.

What core can and cannot do, checked before any of these were drawn. when is declarative and accepts equals: false, so a mode toggle works. compute() may derive anything from the parameters, so people = budget / spend costs nothing. But option lists are static — optionEntries reads field.options as an array or an object, never a function — so no control's labels can be computed from another parameter, and there is no two-way drag where moving one slider moves the other. Every candidate below stays inside that, so none of them needs a core change.

Each rail is built by core/controls.js from a real parameter spec at the real 300 px track, and every one is live — drive it. Under each is what the figure would then say, and what that setting costs, run against the widget's own budgetStudy.
