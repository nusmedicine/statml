Your three points on the B build. Nothing in the widget has been changed for this page; every sketch is a proposal.

§1 · The gaps in the print are torch's own, and the bracket the new dimension adds can be lit

torch separates blocks with blank lines, one per level: the two rows of a [2, 2, 1, 5] print sit inside single brackets, one blank line separates the dim-1 blocks, two blank lines separate the dim-0 blocks. The widget prints exactly that, by torch's own rule (the print is generated, not typed). What is missing is the answer to "which bracket is the new one": it is the pair round each row, and the proposal is to draw that pair in the highlight colour, in the result of unsqueeze and in the source of squeeze — the same colour the drawing uses for the frame it adds (§2), so the two say the same thing.

§2 · The drawing: a size-1 dimension as a dashed frame round what it wraps

Today a size-1 dimension is drawn as whatever its position happens to be: a frame level at dims 0–1, a one-row grid at dim 2, one-cell rows at dim 3 — so in your screenshot the new dimension was the "0" row index beside each grid, which is why it was hard to see. Proposal: a size-1 dimension is always drawn as one dashed frame in the highlight colour, labelled dim k = 0, round each block it wraps: round everything for position 0, round each grid for position 2, round each cell for position 3. The rest of the tensor is drawn as the tensor without that dimension, so [2, 2, 1, 5] looks like the [2, 2, 5] with a frame round each row — an extra bracket looks like an extra frame. In both views; the same frame in the source of squeeze, so what squeeze removes is the frame that unsqueeze added. The [1, 2, 2, 2, 5] frame of round 21 is this rule's first case.

§3 · When squeeze names a dimension that is not size 1

No error is the right answer: torch's squeeze(dim) returns the tensor unchanged when that dimension is not size 1, which is what your cell 34 says ("otherwise it is unchanged"). The widget does that — the shape stays [2, 2, 1, 5] and the caption says why — but it builds the result value by value as if something had been done, so it looks like success. Proposal: when nothing is removed, nothing is built. The Result band draws U again at once, headed Result · unchanged, with the line that says why; the buttons are inert ("nothing to move"); the readout's Result shape says unchanged. Squeeze of a size-1 dimension keeps its walk, because there the values do move.
