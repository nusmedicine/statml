The engine is real, and the geometry is the shipping one. Four named 3 × 3 kernels — horizontal edge, vertical edge, blur, centre-surround — run over the image, then ReLU, then 2 × 2 max pooling, then four more over the pooled maps. Every feature map on this page is that arithmetic. Four channels of thirty-two. A convolution here computes four maps where the network computes 32 or 64, and each second-block map runs one kernel over the pooled map of the same index.

§2 · The example image

The input today is a Gaussian blob, a smaller blob and noise of 0.18. Four candidates against it, each procedural and seeded, each drawn at 28 × 28 with its four conv1 maps beside it, and again at 64 × 64 with the horizontal-edge map. Every generator is written in coordinates of n / 28, so the same picture is drawn at both sizes and only the sampling changes.

How the contrast is measured. Each generator returns a region label as well as a value, from the noise-free geometry. Boundary is a pixel with a four-neighbour in a different region; flat is a pixel whose 5 × 5 neighbourhood is one region. The number printed is the mean |response| of a kernel over each set, and their ratio. Blur has no edge response to measure — its output is the local mean, so its magnitude follows the brightness of wherever it is — so blur is reported instead as the difference between object and field after blurring, which is what makes a shape readable in that map.
