A display switch mid-press, every widget

Widget 70's ship found that core keeps a running loop going through a display change, so a widget whose advance steps whichever page a display parameter names runs the other page's press unasked when the reader switches mid-press; widget 69 had it too (2026-09-19, fixed 2026-09-20). This page asks every widget the same question, with no knowledge of its internals: for each display control, is the figure after press → switch the same whether the press was interrupted five frames in or allowed to finish first — and is it the same after switching back? A data control resets the animation on both runs, so it passes trivially; a display control that re-targets the drive does not. NOT DEPLOYED.
