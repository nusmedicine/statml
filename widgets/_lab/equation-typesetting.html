Typesetting the fitted equation

No KaTeX and no MathJax — the repo has no runtime dependencies and no build step, and both are npm packages. What is available without either: unicode drawn on the canvas, hand-typeset runs drawn on the canvas, and native MathML in the DOM. Every canvas figure is measured against 486 px, the widget's inner width at the 550 px fingerprint baseline, and the equation block reserves three lines.

MathML — one block against one per term

A single <math display="block"> does not line-break: automatic linebreaking is in the spec and effectively unimplemented, so a thirteen-term equation just runs off the side. Emitting one inline <math> per term inside an ordinary flowing block fixes that — the browser wraps between them like words. So MathML is viable; what it costs is leaving the canvas.

8 · Does MathML work here, and what if it does not?

typeof window.MathMLElement === "function" reports whether the interface exists, not whether the browser lays maths out. A real capability test measures instead: an <mfrac> stacks a numerator over a denominator, so it must be markedly taller than the same characters inline. If it is not, the browser is treating the tags as unknown inline elements.
