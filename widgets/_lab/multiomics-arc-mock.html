0 · What the measurement found

The lesson reproduces. mixOmics 6.34 on the lesson's saved files gives 05 cell 24's test BER 0.3308 to four places and 03 cell 13's PLS correlations 0.889 · 0.886 · 0.779.
99 holds on the real blocks. Each block's own PC1 correlates 0.37–0.51 with the other block's PC1; PLS component 1 correlates 0.78–0.89 and keeps 1–2 points less of each block's variance (§1's table).
100's claim narrows. The weight barely moves the agreement (0.85 → 0.87, weight 0 → 1) and moves the CV error 0.20 → 0.26; 8 of 25 component-1 mRNA genes change. The external test set (102, no RPPA) leans the other way (0.29 → 0.25) — too few samples to rank weights.
101's claim depends on the set-up. On the lesson's own pipeline the leak is small (test 0.304 vs 0.312). On shuffled labels, BH ≤ 0.001 passes no feature at all; a fixed top-k filter before CV scores 0.34–0.54 at n = 60 and 10 features where chance is 0.75, and the gap shrinks as samples or features grow.

3 · Slot 101 selection-bias — choosing features with the labels, before or inside cross-validation (02 cells 37–50; 03 cells 18–24)

The two orders. 02 filters every block by an ANOVA against the subtypes, using all 507 labelled samples, the 102 test samples among them; 03 then cross-validates inside the features that survived. A filter run inside each fold sees only that fold's training labels. How much it matters (right): the subtype labels shuffled, so there is nothing to find and chance is 0.75. Filtering first scores far better than chance when few samples and few features are kept (n = 60, 10 features: 0.34–0.54); the gap closes as either grows, and the lesson sits at the far corner (405 samples, thousands of features).

Two pages, Null · Lesson. Null: the shuffled labels, Samples 60 · 120 · 405, Features kept 10 · 50 · 500, Filter Before CV · Inside each fold; a press Cross-validate runs the ten folds one at a time, the fold's predictions landing in a confusion matrix, then its BER drops onto a strip with chance marked; ten seeds a cell, computed ahead. Lesson: the same two orders on the real labels and the lesson's own blocks: 8,383 · 8,103 · 71 features against 7,440 · 6,648 · 71, test BER 0.304 against 0.312. The page says what the numbers say: on this data the leak costs little, because so much survives the filter; the order is still wrong, and the Null page shows where it is not harmless.

4 · What the lesson says, for you to fix (now measured)

  1. 02 cells 40, 45, 50: filterANOVA runs on meta.data.all, so the 102 test samples' subtypes chose the features. Measured: filtering on the 405 training labels instead keeps 7,440 · 6,648 · 71 features (7,340 and 6,563 shared with the lesson's), and the test BER at 4 components goes 0.304 → 0.312; CV 0.230 → 0.246. Small here, but the fix is one line: pass meta.data.train.
  2. 05 cell 23 predicts from WeightedVote$centroids.dist[,2]. The columns are cumulative components, so this uses components 1–2 where 03 chose 4. Reproduced exactly (BER 0.3308, 18 non-POLE samples called POLE); with [,4] it is 0.304 and 7. [, ncomp] or [, "comp4"] fixes it.
  3. 03 cells 10–14 read the design weight as a measured relationship and suggest 0.7–0.9 from the PLS correlations. Those correlations are measured without the subtypes; inside DIABLO the components agree at 0.85 even at weight 0. CV BER: 0.195 at 0, 0.213 at 0.1, 0.248 at 0.9.
  4. 04 cell 11: plotIndiv is said to project on "the first 2 principal components"; they are DIABLO's components, one plot per block.
  5. 02 cell 37: the ANOVA filter is said to keep genes "more likely to be differentially expressed (and hence have a higher variance)". It keeps genes whose subtype means differ; that is a different set from the highest-variance genes, which is what the variance filter it sets aside would keep.
